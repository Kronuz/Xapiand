## 1. Features

### F1 `group-heal`: replication groups grow, heal and run in the simulator

Repository strata. Folds `group-install`, `group-sim`, and `phase3r`'s release scope (its A1 to A4
and A7, which `group-sim`'s Decisions already split into these quests).

Outcome. A `strata::group` grows and heals. A learner installs a checkpoint, the segment pack and the
application file set in one transfer, catches up from the log and is promoted. Voters are replaced
and removed one step at a time. A damaged segment, manifest or file fences its replica, which
reinstalls at or below commit. A witness stores the log, never applies, and leads only to hand off
(D113 Q3 (a)). strata's deterministic simulator, ported from `design/simulator` onto `main`, drives
the group through crashes, power loss with torn and reordered writes, partitions, clock skew and
membership changes, and its checker proves linearizability over write and `linearizable` get-by-id
histories. It is the Phase 3R item on the release's scope, and the group Xapiand's replicas need.

Files: `include/strata/group/**`, `src/group/**`, `test/group/**`, `sim/**`,
`docs/mechanisms/{replication-group,group-install,simulator}.md`, `docs/gates/phase-3r.md`, and
`CMakeLists.txt` only for `sim/`'s `add_subdirectory` line if the prerequisite quick fix named in
`group-sim`'s Decisions has not landed. `track-d` gives up `sim/**` and `docs/design/simulator.md`.

Needs `group-core`, which shares its files.

Criteria:

- C1 A learner installs a 64 KiB-chunked segment pack and file set from a pinned manifest, catches
  up and is promoted; replace and remove pass across leader changes; digests, file set included,
  equal the leader's; a mutant install that skips the file set fails, and a retried install sends
  only the files the learner lacks or holds short, counted in bytes (tests with values).
- C2 Catch-up after a checkpoint: `group-core`'s schedules at seeds 8, 12, 16, 18, 23, 24 and 27
  (3 voters), plus 40 new seeds of the same shape, settle with checkpoints taken while a replica is
  down (D109); a mutant that drops `SnapshotNeeded` fails them (tests).
- C3 A damaged segment, manifest or application file fences its replica, which reinstalls at or below
  commit and serves no corrupt byte, one test per file class; a simulated device that persisted a
  non-prefix subset of its writes since the last flush is answered by the journal's checksums and C3
  repair (a test with values).
- C4 A two-data-voter-plus-witness group survives the loss of any one member; the witness stores the
  log, never applies, and leads only to hand off (simulation-style tests).
- C5 The simulator runs in the suite at a short budget per voter count (3 and 5), covering every
  fault class of `group-sim` A1 and D7's 0-to-1 growth window; the checker passes on write and
  `linearizable` get-by-id histories and checks `prefix` reads for a consistent prefix only; each of
  `group-sim` A3's four mutants fails it.

After landing:

- Review: one reviewer, lens `durability`, carrying correctness (install bytes on the wire, repair).
- Gate rows (Phase 3R, `group-sim` A1): at least 10^7 steps over at least 1,000 seeds for 3 and
  5 voters, as `--later` light jobs at priority -1 on the macOS host (deterministic, no timing), in

  1,000 groups, after the release by D125), A8 (FreeBSD and arm64 rows; D35, D36).

### F2 `placement`: the root authority places and repairs groups

Repository strata. Folds `placement-root` and `placement-repair`.

Outcome. One strict-consensus root group holds the node directory and one namespace record per
index, keyed by path, with nested paths distinct. Placement chooses `rf` distinct nodes with the
fewest groups and spreads leaders. Records are scanned in key order by a caller's matcher that
seeks past keys it cannot match, so Xapiand's `Glob` drives a pattern scan under a work bound. The
root keeps every shard at its `rf`: a node down past `--replace-after` is replaced, a drain moves a
node's replicas, `number_of_replicas` grows and shrinks through D7's steps, leader balance defers
while a chunked command is open, and a new root voter installs the root's records.

Files: `include/strata/placement/**`, `src/placement/**`, `test/placement/**`, `bench/placement/**`,
`docs/mechanisms/placement-{root,repair}.md`.

Needs `group-core`; lands after `group-heal` (repair uses its learner and membership steps, so it
builds against `group-heal`'s contract from `group-install`'s quest file and runs beside it).

Criteria:

- C1 Nodes and namespace records create, read and delete, with `twitter` and `twitter/user` distinct;
  placement puts `rf` distinct nodes per shard and at most one leader more than the mean per node
  (a property test); the authority survives the loss of any minority of voters with no committed
  record lost (a simulation-style test).
- C2 The seekable scan returns exactly what a brute-force filter returns for the reference glob
  matcher (`*`, `?`, classes, `**`, `_all`, a leading `*`, `**/x`, `-` exclusions, `.` names never
  listed, nested paths), and the keys it visits for a one-subtree pattern stay within a stated
  multiple of that subtree (a property test with a counter).
- C3 Replace past `--replace-after`, drain, and `number_of_replicas` 0, 1, 2, 1, 0 under writes lose
  no acknowledged write, leave digests equal after each step, and keep every shard at `rf` wherever a
  replacement exists; an `rf = 1` group waits for its node (simulation-style tests).
- C4 Leader balance defers a transfer while the group reports an open multi-entry command and makes
  it once the command ends; a mutant that transfers anyway aborts the command (a test with values).

After landing:

- Review: one reviewer, lens `correctness` (the records are pre-release bytes, D30).
- Measurements, one `exclusive` job of at most 10 minutes each on the macOS host (D59): the root at
  10^6 namespace records of 5 shards (memory at most 256 MiB, checkpoint time and bytes, creations
  per second from 64 clients with p50 and p99, a node's cache at 10^4 entries), and a new root
  voter's install of those records against D5's 2.5 s per 300 MB. The cluster gate's R10 cites
  them.

### F5 `cluster`: Xapiand in a cluster

Repository Xapiand. Folds `shard-rpc`, `cluster-membership`, `shard-groups`, `distributed-search`,
`cluster-api`, `cluster-migration`, and `phase7b`'s release scope (A1 to A3 and A7; A4 and A5 are the
scale rows after the release, D91, D113 Q4). About 6,600 lines by the design's estimates
(`docs/design/cluster-release.md` section 5). None of the six ships alone: the RPC has no caller
without groups across nodes, membership is wired by the shard map, and the shard map without fan-out
search returns partial results, so they are one feature, built by parallel tasks.

Outcome. An index's shards live as groups on `rf` nodes the root chooses, and any node serves any
request. Nodes join from `--join` seeds with one certificate each (D113 Q5 (b)), and keepalives to
the root leader mark a node `suspect` then `down`. A write reaches the group leader with at most one
forward; `linearizable` reads at the leader after its quorum probe, `prefix` at any replica. A search
from any node fans out over the shard RPC with exact statistics and merged aggregations, and patterns
run over the root's records instead of the local directory walk. Users set `number_of_replicas`, read
`/:cluster/health`, `:info`'s groups and `/:nodes`, drain a node, and grow one node with data into a
cluster and back. The docs and changelog describe it.

Files: the union of the six quests: `src/cluster/**`, `tests/cluster/**`, `harness/cluster/**`
(except `gate*`), `src/index_resolver_lru.*`, `src/database/{pool,shard,handler}.*`, `src/opts.*`,
`src/manager.*`, `src/engine/{search,strata/search}.*`, `src/server/search_views.cc`,
`src/index_pattern.*`, `src/walk_gate.h`, `tests/test_index_pattern.cc`,
`tests/fuzz_index_{pattern,expand}.cc`, `docs/mechanisms/{shard-rpc,cluster-membership,shard-groups,distributed-search}.md`,
`docs/src/content/docs/{options,installation,architecture,faq,changelog,upgrade}.md`,
`docs/src/content/docs/{reference-guide,tutorials}/**`.

Tasks (parallel writers, `campaign start cluster --task T --files GLOBS`): `rpc`, `membership`,
`shard-map` (routing, options, manager), `search`, `api` (settings, health, docs, changelog),
`migration`.

Needs `journal-replaces-wal` (it shares `shard`, `handler`, `pool`, `manager`, `opts` and
`search_views`) and F3's consensus pin; after `group-heal` and `placement` (strata pin). To start

`tests/cluster/**`, `harness/cluster/**` and the mechanism notes, so the `rpc` and `membership` tasks
run once F3 lands, and widens it to the shared files when F4 lands.

Criteria:

- C1 Section 1's parity checklist, items 1 to 6, passes on 3 and 5 processes (the `cluster` check).
- C2 Writes from any node: one forward with a fresh hint and at most two with a stale one, the
  receiving node following the redirect; 503 with `Retry-After` under no quorum or on a second miss;

### F6 `turn-log-parity`: the turn log at par with RocksDB

Files: as the quest. Needs `document-gate` and `group-core` (both hold `include/strata/core/**` or
`index.hh`).

  reader does not; a mutant without the mechanism fails (a test with values).

  covered fails `log_lost` or reports its possible loss; a mutant that opens every index fails.
- C3 A transaction above 64 MiB up to the unlogged limit, and a batch past 1 MiB, are all-or-nothing
  across a crash at every point (the crash model, which gates: a durability mechanism changes), each
  with a mutant.
- C4 Group commit: with K concurrent writers, no writer that arrives during a barrier waits more than
  the next barrier, counted per writer; a mutant that defers it a whole barrier fails (a test).
